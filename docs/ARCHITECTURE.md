# DRIFT Architecture Notes

DRIFT stands for **Decoupled Reasoning with Implicit Fact Tokens**. The core
idea is to separate long-context knowledge extraction from downstream
reasoning.

## High-Level Flow

```text
Long document + query
  -> chunk long document
  -> knowledge model compresses each chunk into <|CPS|> hidden states
  -> concatenate implicit fact tokens across chunks
  -> project knowledge-model hidden states into reasoning-model embedding space
  -> replace reasoning-model <|CPS|> embeddings
  -> reasoning model generates the answer
```

The compression is latent. The knowledge model is not asked to output a normal
text summary for the reasoning model to read. Instead, the hidden states at the
compression-token positions become **implicit fact tokens**.

## Main Components

### Knowledge Model

The knowledge model reads a document or chunk together with an instruction and,
for query-aware stages, the query. Its role is to encode useful information into
the hidden states corresponding to `<|CPS|>` tokens.

The knowledge model can come from a different model family than the reasoning
model.

### Reasoning Model

The reasoning model receives prompts containing `<|CPS|>` placeholders. Before
the reasoning model runs, those placeholder token embeddings are replaced with
projected implicit fact embeddings generated by the knowledge model.

### Projector

The projector is a three-layer MLP. It maps hidden states from the knowledge
model's hidden size to the reasoning model's hidden size.

### Compression Token

The compression token is:

```text
<|CPS|>
```

Both tokenizers must contain this token. Its token id is used to locate the
positions where hidden states are extracted or embeddings are replaced.

## Training Stages

| Paper term | Legacy phase | Objective |
| --- | --- | --- |
| LFRP | `pretrain_1` | Reconstruct document from static latent facts. |
| QAFT-DC | `pretrain_2` | Reconstruct evidence from query-aware latent facts. |
| QAFT-QA | `simple_sft` | Answer questions from implicit fact embeddings. |

Public APIs and CLIs should use the paper names (`lfrp`, `qaft_dc`,
`qaft_qa`). Legacy names can remain as aliases while migrating old scripts.

## Multi-Context Inference

DRIFT is trained on single-context QAFT but evaluated on multi-context
ultra-long inputs without additional multi-context fine-tuning. The long
document is split into chunks, each chunk is compressed independently, and the
resulting implicit fact token sequences are concatenated in the original order.

Expected evaluation fields:

```text
Document
Question
```

Optional fields:

```text
User_instruction
answer_prefix
```

Single-GPU evaluation should support `--num-gpus 1` and an optional `--device`
argument. Multi-GPU evaluation should preserve the legacy worker-per-GPU
sharding strategy.
